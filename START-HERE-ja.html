ことばの窓 v0.8.0-rc.1 はじめての試用

Pythonを入れたことがない人が、公式Pythonの導入から、ZIPの展開、Chromeでの英文Word翻訳、結果の保存まで行うための手順です。まず付属の架空の例文で試します。重要な文書や個人情報は使わないでください。

v0.8.0-rc.1は公開試用版（pre-release）です。既存環境のWindows/Mac 2Bで短文・Word文書の取込・翻訳・保存を確認しました。WindowsではWord本体での再読込も確認しています。利用者本人のWord文書、新規Python導入からの通し操作、今回版の新規モデル取得、Finder/Gatekeeper経路、MacのWord本体表示は未確認です。詳しい実測と制限はVERIFICATION-ja.mdを確認してください。インストーラ画面の写真・赤枠付き説明は未収録です。

すでにPythonを入れている方へ

通常版CPython 3.12 / 3.13 / 3.14の64bit版があれば、Python導入を飛ばせます。下記のバージョン確認を行い、起動時にも使われるPythonの場所と版を確認してください。3.15以降、free-threaded版、Windows ARM64/32bit版はこの試用の対象外です。

今回の実測はWindowsの通常版CPython 3.14.10（64bit）とMacのCPython 3.12.16（arm64）です。既存Pythonからの起動・2B翻訳とWord保存を確認しました。新規Python導入からの通し操作とは区別します。

用意するもの

- WindowsはWindows 11 64bit。ブラウザはGoogle Chromeを使います。Windows 11以外のWindows・他ブラウザは未確認です。
- Macの確認環境はMac mini M6・メモリ32GBです。他のMacへの対応保証ではありません。
- Google Chromeがなければ、公式 https://www.google.com/chrome/ から導入してください。アプリが勝手にインストールすることはありません。
- モデルの初回取得にはインターネットが必要です。2Bモデルは約1.81GB。実行部などの容量と必要な空き容量は、取得前の画面にも表示します。
- Windowsの実測はRyzen 5 8645HS・メモリ16GB、CPUでの実行です。16GBを最低要件と確定したものではありません。内蔵グラフィックスPCでは2Bを試す目安にできますが、他構成の動作を保証するものではありません。
- Microsoft Wordのインストールは、この試用には不要です。付属の.docxをアプリから読み込みます。

1. WindowsにPythonを入れる

1. 公式 https://www.python.org/downloads/windows/ を開きます。広告や別サイトのダウンロードは使わないでください。
2. Python install managerの公式ページ https://www.python.org/downloads/release/pymanager-264/ にあるInstaller (MSIX)をダウンロードします。
3. ダウンロードしたファイルを開き、内容と発行元を確認してインストールします。警告の内容が分からないときは無理に進めず、画面の内容を確認してください。セキュリティ設定を無効にする必要はありません。

このとき最新のPython 3.15が入っても、まだアプリの準備は完了していません。この試用版は3.15では起動しないため、次の手順で3.14を追加します。3.15を削除する必要はありません。
4. スタートボタンを右クリックし、ターミナル（PowerShell）を開きます。通常権限で構いません。
5. 次の1行をコピーして貼り付け、Enterを押します。数字の「3.14」まで含めて入力してください。

pymanager install 3.14

6. 終わったら、次の1行で確認します。

py -V:3.14 --version

Python 3.14.x と出れば導入した版を確認できます。2026-11-11に公式ページで確認した3.14系の最新版は3.14.10です。導入後にターミナルを開き直してもコマンドが見つからない場合は、そのエラーを確認してください。既存のPythonを一律に削除したり、OSの安全設定を変更したりしないでください。

すでにPythonがある方は、3.14の代わりに3.13または3.12を指定して確認できます。対応版があれば再インストールは不要です。

公式説明: https://docs.python.org/3/using/windows.html#python-install-manager

2. MacにPythonを入れる

1. 公式 https://www.python.org/downloads/release/python-31410/ を開き、macOS installerをダウンロードします。Apple Siliconにも対応するuniversal2版です。
2. ダウンロードした.pkgを開き、画面の説明と利用条件を読んで標準インストールを進めます。Macの管理者認証が必要になる場合があります。パスワードはMac自身の画面にだけ入力し、メールやチャットなどで他の人へ送らないでください。
3. アプリケーションフォルダの「Python 3.14」にある「Install Certificates.command」を開き、完了を確認します。
4. 新しいターミナルを開いて、次の1行を入力します。

python3.14 --version

Python 3.14.x と出れば導入した版を確認できます。すでに3.13または3.12を入れている方は、その版を指定して確認し、導入を飛ばせます。「python3」だけではMac付属の古いPythonを選ぶ場合があるため、版番号付きで確認します。

Python自体はIntel Macにも提供されていますが、それは「ことばの窓」のIntel Macでの動作確認を意味しません。
公式説明: https://docs.python.org/3.14/using/mac.html#installation-steps

3. ZIPを全部展開する

1. 試用ZIPをダウンロードします。
2. WindowsはZIPを右クリックし「すべて展開」を選びます。ZIPの中から直接起動しないでください。MacはZIPを開いて展開します。
3. 展開後のフォルダを開きます。起動ファイルだけを別の場所へ移さず、フォルダの中身をまとめたままにします。

4. 起動する

Windowsは「Open-Windows.cmd」、Macは「Open.command」を開きます。

起動時の画面に、使われるPythonの場所とバージョンが表示されます。対応Pythonがない場合は導入案内が出ます。ほかのAIツールや、それに同梱されたPythonは必要ありません。

準備ができるとGoogle Chromeにアプリ画面が開きます。Chromeがない場合は案内を確認してください。起動用のウィンドウは、使っている間は閉じずに置きます。ポート使用中の場合は、先に開いたアプリがないか確認します。他のアプリを強制終了する仕組みではありません。

5. 初回だけ2Bを準備する

1. アプリの「2Bの準備内容を見る」を押します。
2. モデル・実行部の容量、取得先、保存先、利用条件を読みます。取得先はHugging FaceとGitHubの公式配布です。この操作で翻訳する文章を送ることはありません。
3. PLaMoの利用条件を確認します。個人の私的・非商用利用と、商用利用の条件は異なります。商用の場合は利用者自身の登録等が必要です。アプリ作者の登録を代わりには使えません。
4. 条件を確認するチェックを自分で入れ、ダウンロードを開始します。途中で止める場合は画面の中止ボタンを使います。
5. 完了まで待ちます。取得した内容の容量とハッシュが一致したものだけ使います。失敗した場合はエラーを確認し、画面の案内から再試行します。
6. 「このモデルを使う」でモデルと実行部の場所を入力欄へ反映します。利用条件の確認欄を確認し、「翻訳AIを読み込む」を押します。ダウンロードしただけではモデルは自動で動きません。読み込みを押すと、まずファイルをSHA-256で検査します。2Bでは少し時間がかかります。検査中も「モデルを停止」や「アプリを終了」で中断でき、中断した後に遅れてモデルが起動することはありません。

2回目以降の起動（もう一度ダウンロードしない）

一度2Bを準備したパソコンでは、ダウンロードをやり直す必要はありません。アプリを開き直すと「翻訳AIを準備」の欄に「以前準備した2Bが見つかりました」と表示され、「見つかった2Bを使う」ボタンが出ます。

1. 「見つかった2Bを使う」を押します。モデルの場所が入力され、実行プログラムの欄は空のまま自動検査されます。
2. 利用条件の確認欄を確認し、「翻訳AIを読み込む」を押します。内容はこのときSHA-256で検査します。

ボタンを押すまで、モデルの選択・読み込み・利用条件への同意は行いません。この表示はファイル名と容量が一致したという意味で、内容の検査は読み込み時です。ボタンが出ない場合（保存先を変えた、ファイルが壊れた、実行プログラムがない等）は、「2Bの準備内容を見る」からやり直すか、下の保存先を指定してください。Windowsでは次の手順で実際のパスへ変換してから「② モデル本体」の欄へ貼り付けます。

自動準備したモデルの保存先（最後のフォルダ名は固定の版番号です）:

- Windows: %LOCALAPPDATA%\KotobaNoMado\models\plamo-2b-gguf-q4km\4f672106b847200bfdc0f6af6c321cd94eba1aed
- Mac: ~/Library/Application Support/KotobaNoMado/models/plamo-2b-gguf-q4km/4f672106b847200bfdc0f6af6c321cd94eba1aed

Windowsで保存先を手入力する手順: 上の %LOCALAPPDATA% から始まる行を、エクスプローラーのアドレスバーへ貼り付けてEnterを押します。開いたフォルダでアドレスバーをもう一度クリックし、C:\Users\… のような実際のパスをコピーして、アプリの「② モデル本体」へ貼り付けてください。%LOCALAPPDATA% を含む文字列をアプリへ直接貼り付けても展開されません。Macでは上の ~/ から始まるパスを直接指定できます。

モデルと実行部、どちらのフォルダを選ぶ？

ここからはGGUFモデルの指定方法です。「モデル」は翻訳に使うデータ（.ggufファイル）、「実行部」はそのデータを動かすプログラム（llama.cpp）です。モデルだけでは翻訳できません。画面では「実行プログラム」と表示し、この手順書では短く「実行部」とも書きます。同じものです。Windowsの実行部はexeとDLLなどをまとめたセットなので、ZIPをすべて展開し、中身を一緒に保ってください。モデルと実行部は別々のフォルダに置くことをおすすめします。

1. まず「使う翻訳AI」でモデルのサイズ・形式を選びます。最初はMacでもWindowsでも2B GGUFが選ばれています。一覧は「このパソコンのOSで動作確認済み」と「読み込めるが未確認」に分かれ、31Bなど大きなモデルには「大容量」と表示します。大きいモデルは多くのメモリと時間を使うため、初めての方は2Bのままにしてください。Windowsの8B・31B GGUFは翻訳成功未確認の追加試用（未検証試用の警告と確認は継続）、Macの8B・31B GGUFは非対応です。
2. 「既存ファイルを使う・詳しい設定」を開き、「② モデル本体（GGUF）を保存したフォルダ」欄に、選んだGGUFが入ったフォルダを指定します。ファイルそのものではありません。同じフォルダに2B・8B・31Bがあっても、一覧で選んだモデルの固定ファイルだけを使います。大きいモデルへ勝手に切り替わることはありません。
3. 「③ 実行プログラム（llama.cpp b11938）のフォルダ」欄には、対応するllama.cpp b11938をすべて展開したフォルダを指定します。Windowsではllama-server.exeと同じ配布物のDLLなどが入ったフォルダです。モデル保存フォルダやZIPファイルを指定する欄ではありません。すでに2Bを準備した方は、下記の空欄での自動検査も使えます。

たとえばWindowsでは、モデルを C:\KotobaModels に、実行部を C:\KotobaRuntime\llama-b11938 に置き、それぞれの欄にそのフォルダのパスを入力します。これは置き場所の例で、その名前のフォルダが最初からあるという意味ではありません。対応版以外の実行部を混ぜないでください。

### 「フォルダを選ぶ」が固まる、フォルダを選べないとき

この2つの欄の「フォルダを選ぶ」はフォルダ選択です。Windowsではエクスプローラーで目的のフォルダを開き、上部のアドレスバーをクリックして、表示されたフォルダのパスをコピーします。アプリの該当欄へ直接貼り付けて構いません。MacではFinderで目的のフォルダを選択し、Optionキーを押しながら「編集」メニューの「…のパス名をコピー」を使って貼り付けます。GGUFやexeのファイル名は付けず、フォルダまでのパスを入力してください。Windowsの「パスのコピー」で前後に付く引用符（"）は、そのまま貼り付けても自動で取り除きます。

### 実行部を空欄にしたときの自動検査

空欄の場合は、2Bの自動準備で使う次の固定キャッシュだけを調べます。「既存の実行プログラムを再確認」で検査をやり直せます。パソコン全体やモデル保存フォルダを探し回る機能ではありません。

- Windows: %LOCALAPPDATA%\KotobaNoMado\runtimes\llama.cpp-b11938-win32-x64
- Mac（Apple Silicon・対応する2B GGUF用）: ~/Library/Application Support/KotobaNoMado/runtimes/llama.cpp-b11938-darwin-arm64

Windowsの %LOCALAPPDATA% はユーザーごとの保存場所です。エクスプローラーのアドレスバーに上のパスを貼り付けると、その場所を開けます。Macの ~ はホームフォルダです。Finderの「移動」→「フォルダへ移動」で上のパスを開けます。

画面では「検査中」「確認済み」「見つからない」「不一致・破損、または安全に確認できない」を区別して案内します。「確認済み」は固定版の実行部ファイルの検査結果であり、翻訳や8B・31Bの実機動作を保証する表示ではありません。「見つからない」なら対応実行部を準備するか、保存済みの場所を指定します。「不一致・破損、または安全に確認できない」なら表示された場所と内容を確認してください。

自動検査では、公式2Bキャッシュのファイル名一覧が完全に一致することと、対応する全ファイルのSHA-256を確認します。余分なGGUFが同居していても「不一致・破損、または安全に確認できない」として拒否します。一方、実行部フォルダを手動で指定する場合は、従来どおり対応する全実行部ファイルのSHA-256と追加DLLなどの有無を検査し、GGUFの同居は許容します。GGUFが同居するため自動検査だけが不一致になる場合は、その実行部フォルダを手動入力してください。手動指定でも実行部の検査を省略するわけではありません。ファイルを自動で移動・整理することは一切ありません。

自分で実行部フォルダを入力した場合は、その場所を優先します。リンク（ショートカットではなくシンボリックリンク等）は使えますが、検査と起動はリンク先の実体のフォルダで行います。ネットワーク上の場所（共有フォルダ、ネットワークドライブ）にある実行プログラムは、検査後に他の人が差し替えられるため読み込みません。このパソコンのドライブへフォルダごとコピーしてください。種類を判別できない場所は従来どおり受け付けます。モデル本体（GGUF）は全体をSHA-256で検査するため、この制限はありません。誤った場所・別の版・破損したファイルでも、別の場所へ黙って切り替えることはありません。空欄での検査は、ダウンロード、ファイルの移動、設定変更、利用条件や未検証試用への同意を行いません。見つかっても自動では読み込みません。「翻訳AIを読み込む」を押す時にもSHA-256を再検査します。

6. 英文Wordを日本語にする

1. 翻訳元を「英語」、翻訳先を「日本語」にします。
2. 「文書を翻訳する」の「ファイルを選ぶ」を押します。
3. 展開したフォルダ内の samples にある「English-to-Japanese.docx」を選びます。
4. 読み込んだ文章に、図書館についての英文が3段落あることを確認します。抜けや順番を確認する黄色の一般注意はエラーではありません。
5. 最初は標準の長さ・設定で「文書を翻訳する」を押し、結果を待ちます。
6. 日本語になったか、朝9時・月曜休館・5冊・2週間という意味や数字が残っているか確認します。詳しい確認項目はsamples/CHECK-ja.txtです。翻訳はいつも人が確認してください。

.docxが対象です。古い.doc、画像だけの文書、パスワード付きファイルはこの試用に使いません。

読み込むのは文字だけです。太字・見出し・表の罫線・画像などの書式は読み込まず、保存するWordにも残りません。Wordが自動で付ける番号や行頭記号（「1.」「第1条」「・」など）も文字としては入らないため、その場合は黄色の注意が出ます。番号が必要な文書は、読み込んだ文章に書き足してから翻訳してください。見出しのスタイルで付く番号も注意の対象です。隠し文字（非表示に設定した文字）は読み込まれるため、注意が出たら不要な部分を削除してください。連続した空行は1行の空行にまとめ、保存するWordでも空行1行として残します。

7. 保存して終わる

1. 「ファイルの形式」を「Word（.docx）」、保存する内容を「原文と訳文を交互に」にします。
2. ファイル名を確認し、「このパソコンに保存する」を押します。
3. Chromeのダウンロード一覧から保存場所とファイルを確認します。翻訳できなかった部分があるときは、保存したファイルのその場所に「［この部分は翻訳されていません］」と入ります。保存したWordの題名（プロパティ）には元のファイル名を書き込みません。元の英文Wordを上書きする必要はありません。
4. 「翻訳AIを止める」、続いて「アプリを終了」を押します。Chromeのタブだけを閉じても、アプリ本体は動いている場合があります。

Windowsで別途取得した8B・31Bを指定する

この追加試用版では、公式固定版のPLaMo 8B・31B GGUF Q4_K_Mを外部ファイルとして指定する経路を用意しています。8Bはメモリ保護停止の試行報告があり、翻訳成功は未確認です。31Bは未試用です。CPUで実行し、必要メモリや速度は保証できません。自動取得とGPU利用には対応していません。使えるのは指定形式・指定版だけで、任意のAIモデルではありません。

先に翻訳結果を保存してAIを停止し、「使う翻訳AI」で対象を選びます。「既存ファイルを使う・詳しい設定」でモデル保存フォルダと対応llama.cppを指定し、利用条件と未検証試用の確認を入れてから読み込みます。未検証試用の追加確認は、読み込みの試行ごとに必要です。フォルダの違いと入力方法は上記「モデルと実行部、どちらのフォルダを選ぶ？」を参照してください。詳細は EXTERNAL-MODELS-ja.md にもまとめています。次の公式固定版ページから、Q4_K_Mのファイルを取得してください。

8B公式固定版:
https://huggingface.co/pfnet/plamo-3-translate-8b-GGUF/blob/c67efa4eefdc14d3c97bf8f4f35ee58e2ecd2f42/plamo-3-translate-8b-Q4_K_M.gguf

31B公式固定版:
https://huggingface.co/pfnet/plamo-3-translate-31b-GGUF/blob/8b797b290907c84403877cb9d03150929f10b467/plamo-3-translate-31b-Q4_K_M.gguf

実行部は、2Bの自動準備で取得したものを再利用できます。別途取得する場合は https://github.com/ggml-org/llama.cpp/releases/tag/b11938 の llama-b11938-bin-win-cpu-x64.zip です。すべて展開し、実行ファイルとDLL等を一緒に保ってください。別の版やGPU版の実行部は使えません。

8Bのファイルは約5.28GB、31Bは約19.53GBですが、これは必要RAMではありません。検査にも時間がかかる場合があります。最初は2Bで基本操作を確認し、ほかの作業を保存してから追加試用を行ってください。

変更前の版で、WindowsのRyzen 5 8645HS・メモリ16GB（使用可能13.8GB）・CPU実行にて8Bを初回試行しました。実行部の指定後、「メモリ圧迫を検出したためモデルを停止しました（空き指標3%、スワップ増加1881 MB）」と表示され、安全停止しています。このPCでの8B翻訳成功は未確認で、ほかのPCでの成功も未確認です。31Bは未試用です。この8Bの過去試行は今回の2B実測とは別で、16GBのPCすべてで不可能と断定するものでもありません。

2Bに戻すには

1. 残したい翻訳結果を保存してから「翻訳AIを止める」を押します。
2. 「使う翻訳AI」で、以前使っていた2B GGUFを選びます。
3. 「② モデル本体（GGUF）を保存したフォルダ」に、以前の2Bを保存したフォルダを指定します。自動準備した2Bなら、「このパソコンにあるPLaMoを使う」を押すか、上の「2回目以降の起動」の手順に従って保存先を指定します（Windowsはエクスプローラーで実際のパスへ変換してからコピー）。
4. 「③ 実行プログラム（llama.cpp b11938）のフォルダ」を空欄にし、「既存の実行プログラムを再確認」で検出結果を確認します。GGUF同居による不一致なら、対応する実行部フォルダを手動入力します。
5. 利用条件を確認して「翻訳AIを読み込む」を押します。

8Bでメモリ保護停止したPCでは、無理に8Bを再試行せず2Bへ戻してください。今回の案内変更でメモリ保護の閾値は変更していません。保護を無効にしたり、条件を緩めたりする手順ではありません。

翻訳結果を外部へ提供・公表する前に

PLaMoの固定版利用条件には、翻訳結果の利用・公表に関する条件があります。以下は概要で、公式全文を確認してください。

- 通常の翻訳結果の公表では、PLaMo使用の表示を省略できる場合があります。
- 書籍・論文など独立した長文公表物の全部または実質的部分に翻訳結果を用いる場合は、奥付・謝辞・末尾などでPLaMoの使用を明示する必要があります。
- これとは別に、翻訳結果を第三者へ提供・公開する場合、その生成物で学習したモデルにはPLaMoコミュニティライセンスが適用される旨を、相手が認識できる形で表示する条件があります。

私的保存まで一律に文言を挿入する仕組みではありません。この試用版が保存する訳文には、上の表示を自動追加していません。外部へ出す前に必要な表示を確認してください。原文の著作権・機密・個人情報にも別途注意が必要です。

重い・メモリが足りないとき

他の大きなアプリを閉じ、短い文章、長さ4,096から試してください。より小さいモデルを選ぶ場合も、アプリでそのOSに対応・取得可能と案内されたものに限ります。未検証のモデルへ切り替えれば必ず動くとは言えません。

8B MLXはMac32GiB環境で独立した短文5件の動作確認済みです。ただし、このアプリへの組込みは未確認のため、8B MLXは今回の試用では選べません。Windowsの8B GGUF外部指定とは別の方式です。

8B以上を「メモリ16GBまたはVRAM8GBなら動く」と一括では案内していません。8Bと31Bは必要条件が違い、量子化方式や実行方法でも変わります。31BはMac mini M6・32GBで既存MLX環境による動作実績がありますが、今回の自動準備対象は2B GGUFです。小さいモデルのスマホ・古いPC用途は候補の話で、このアプリのスマホ対応を意味しません。

Python 3.15と表示され、Chromeが開かないとき

この試用版はPython 3.12〜3.14を使います。3.15だけがある場合は、Chromeを開く前に停止します。

1. 起動用の黒い画面で何かキーを押して閉じます。
2. スタートボタンを右クリックしてターミナルを開き、「pymanager install 3.14」を実行します。
3. 完了後、「py -V:3.14 --version」でPython 3.14.xと出ることを確認します。
4. 展開フォルダのOpen-Windows.cmdを開き直します。

3.15の削除、既定ブラウザの変更、安全設定の無効化は不要です。コマンドが見つからない場合や3.14確認後も止まる場合は、画面のエラーを確認してください。

分からない画面が出たとき

止まった手順、エラー文、Pythonのバージョン、使ったOSを確認してください。画面を共有する場合は、メールアドレス、個人ファイル名、パスワード、起動用コードを隠します。安全警告を無視したり、ウイルス対策やOS保護機能を切ったりする手順ではありません。
